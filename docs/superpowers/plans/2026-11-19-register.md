# 注册功能启用与补全 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让自助注册端到端可用（注册→回登录→登录→大厅），失败可重试，校验前后端一致，有单测与 E2E 覆盖。

**Architecture:** 复用 RuoYi 既有注册链路（前端 `/register` 页 + `POST /auth/register`），零后端代码改动；仅经管理接口打开 `sys.account.registerUser` 开关（`@CachePut` 立即生效）+ 同步 MySQL 种子；前端原位补两处缺口（失败刷新一次性验证码、校验长度对齐 `RegisterBody`）。

**Tech Stack:** Vue 3 + Element-Plus + vitest/@vue/test-utils；Spring Boot 3 RuoYi-Vue-Plus 6（sys_config）；Python Playwright E2E。

**Spec:** `docs/superpowers/specs/2026-11-19-register-design.md`

## Global Constraints

- **不自动 commit**（用户未要求）→ 本计划所有任务**无 commit 步骤**。
- 不改验证码开关 `sys.account.captchaEnabled`；不改任何后端 Java 代码；不重启后端（配置接口自带缓存刷新）。
- 保留工作区既有未提交的 login/register captcha data-URI 修复。
- clientid `e5cd7e4891bf95d1d19206ce24a7b32e`；localStorage token key `access_token`；admin token 读 `logs/token_admin.txt`。
- 后端校验 exact 值：用户名 `@Length(min=2,max=30)`、密码 `@Length(min=5,max=30)`（`ruoyi-api/.../RegisterBody.java`）。
- 种子只改 `script/sql/ry_vue.sql`（MySQL 方言），其余方言不动。
- 前端命令：`cd boardgame-ui && npx vitest run src/views/__tests__/register.spec.ts`；全量 `npm test`；类型+构建 `npm run build`。
- E2E 命令：仓库根 `PYTHONIOENCODING=utf-8 python logs/e2e_register.py`；验证码识图由实施者读 PNG 后写答案文件握手。
- 注册成功文案保持「注册成功，请登录」+ `router.push('/login')`；不做注册后自动登录、不分配角色。

## Review Focus

1. 一次性验证码：注册失败后重试必须能用**新**验证码成功（旧 uuid 已被服务端删除）→ Task 3 单测 + Task 4 错验证码重试阶段。
2. 重复用户名：报错含「已存在」且页面不卡死、验证码已刷新可再试 → Task 4 重复用户名阶段。
3. 长度边界：用户名恰 2/30、密码恰 5/30 应通过前端校验放行 → Task 2 边界测试。
4. `captchaEnabled=false` 时不渲染验证码、提交体不含 code/uuid → Task 3 回归测试。
5. 已登录访问 `/register` 被路由守卫弹回首页 → Task 4 守卫阶段。

### Task 4: E2E 注册全流程（Playwright）

**Files:**
- Create: `logs/e2e_register.py`
- 产物: `logs/e2e_reg_*.png`、`logs/reg_captcha_*.png`、`logs/e2e_reg_out.txt`

**Interfaces:**
- Consumes: Task 1 开关已开；`/auth/code` 响应 `{captchaEnabled,uuid,img}`；登录页/注册页共用 XHR 捕获机制
- Produces: 注册→登录→大厅全链路浏览器证据；新注册用户（命名避开 admin/bob/carol，如 `dave`/密码 `dave12345`）

- [ ] **Step 1: 写脚本（机制 + 阶段 + 断言）**

机制：init script 包装 XMLHttpRequest，捕获 URL 含 `/auth/code` 的响应体存入 `window.__codeLog`；Python 侧每阶段取最新条目 → base64 写 `logs/reg_captcha_N.png` + uuid 记录 → 轮询等待实施者写 `logs/reg_answer_N.txt`（120s 超时）→ 填入验证码输入框。
阶段与断言（check(name, ok) 汇总打印）：
  1. 匿名访问 `/register` 渲染验证码图；提交**错**验证码（`99999`）→ 错误 toast 且 `__codeLog` 增长（验证码已刷新）→ 识图重试 → 成功 toast「注册成功，请登录」+ URL 落到 `/login`。
  2. 登录页用新账号 `dave/dave12345` + 识图验证码登录 → `/lobby`（或首页后导航大厅）显示昵称 `dave`。
  3. 已登录状态 `goto /register` → 被守卫弹回 `/`（Review Focus 5）。
  4. 退出登录 → 再注册**同名** `dave` → 错误 toast 含「已存在」且 `__codeLog` 再增长（Review Focus 2）。
  5. 截图：注册页、错验证码 toast、大厅昵称、重复用户名 toast。
- [ ] **Step 2: 运行 + 识图握手**

Run: `PYTHONIOENCODING=utf-8 python logs/e2e_register.py > logs/e2e_reg_out.txt 2>&1`（后台）；实施者 Read 各 `reg_captcha_N.png` 解 math 题 → Write 对应 `reg_answer_N.txt`（单用 uuid，一次一答）。
- [ ] **Step 3: 核对结果与截图**

Expected: 全部 check PASS；Read 截图确认视觉无空白/错版。任何 FAIL 先按 systematic-debugging 定根因再修（区分脚本问题 vs 应用问题）。
- [ ] **Step 4: 收尾回归**

Run: `cd boardgame-ui && npm test`（确认 E2E 期间无前端改动引入回归）；向用户汇报：开关状态、修复点、测试 totals、E2E 结果；提醒无需重启后端。
