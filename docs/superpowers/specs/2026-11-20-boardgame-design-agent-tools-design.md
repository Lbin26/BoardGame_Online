# 桌游设计助手 agent 工具链（样本库 + 数值模拟）设计

日期：2026-11-20 · 状态：待批准 · 范围：项目 skill + 独立 TS 工具包 + 样本库数据

## Intent / Why

用户要从零设计新桌游，需要一个"桌游设计师助手"agent：既能把用户自己的模糊点子打磨成型，也能自主产出创意供用户挑选。核心诉求是**结合其他桌游的特点来开发**——把成熟桌游拆成结构化设计档案（样本），设计时从样本取特征做组合 remix，并能说清每个借鉴的来源。平衡验证要有真数据（概率/蒙特卡洛），不是拍脑袋。产出双出口：实体规则书，以及将来可植入 BoardGame_Online 平台的结构化规则输入。

## 用户已决定

- 路线选 **B：知识工作流 + 数值模拟工具箱 + 样本库**（见 Approaches）。
- 设计对象是**从零设计的新桌游**，不是导入已有游戏（那是 import-boardgame skill 的事，两者独立）。
- 最终载体**实体和平台都可以**：核心工具载体无关，导出分两条路。
- 创意来源**二者都有**：用户带点子来打磨，或 agent 自主出创意用户拍板。
- 样本来源**混合**：知名游戏 agent 自主调研（WebSearch + 自身知识），用户想深入参考的游戏可喂规则书。
- 初始样本集：目录既有 7 游戏（象棋、围棋、五子棋、璀璨宝石、王权骰铸、阿瓦隆、伯明翰），之后按需扩充。

## Goals

1. 项目 skill `design-boardgame`（`.claude/skills/design-boardgame/`），`/design-boardgame` 或自然语言触发，覆盖两种入口（带点子 / 求创意）与完整工作流：创意 → 结构化规则草案 → 样本对照 → 数值验证 → 评审 → 迭代 → 导出。每个大阶段有用户确认点。
2. **机制库** `references/mechanisms.md`：30~40 个机制，每个含说明、代表作、可调参数（设计旋钮）、常见坑、常见组合。顶层词汇对齐 `catalog.ts` 的 7 区机制标签。
3. **样本库**：每款样本游戏一份结构化档案（与设计中的新游戏**同一 schema**），含机制组合、回合结构、经济/计分模型、关键数值、"它为什么好玩"、可 remix 特征、证据来源与置信度。种子 7 份由 skill 的 analyze 工作流建出。
4. **结构化游戏格式**（YAML + zod 校验）：元信息、机制标签、组件清单、回合阶段、可参数化子系统（经济/冲突结算/计分/卡牌数值/随机模型）。流程性规则用 markdown 散文写，结构化部分只收"能被脚本模拟的东西"。schema 带版本号，字段设计为将来 C 路线解释器可消费留余地。
5. **数值模拟工具箱**（独立 npm 包 `tools/boardgame-design/`，TS + vitest）：
   - 骰子池概率（精确卷积分布 + 蒙特卡洛）
   - 抽卡概率（超几何分布、牌库构成分析）
   - 经济曲线模拟（N 回合资源产出/消耗，检测通胀/卡死）
   - 冲突结算蒙特卡洛（参数化攻防）
   - 参数扫描（sweep）：某参数取一组值分别跑模拟，输出对比表
   - 配置文件驱动、可复现（带种子 PRNG）；输出 markdown 报告 + JSON 原始数据
6. **设计工作区** `design/games/<key>/`：`game.yaml`（结构化规则）、`rules.md`（流程散文）、`journal.md`（设计决策与迭代记录）、`sims/`（模拟配置 + 报告）、`exports/`（规则书等）。
7. **导出**：实体方向导出结构化规则书 markdown（按模板）；平台方向导出 game.yaml + 实现要点说明（**不含**引擎代码）。
8. skill 纪律：平衡性论断必须引用模拟报告或样本证据；借鉴样本须注明来源；设计决策记入 journal.md。

## Non-goals / Anti-goals

- 不做整局自动对局/自我对局 AI（C 路线，后续独立项目）；不做平台引擎实现、不动后端/数据库。
- 不做目录登记（设计完成后的登记走 import-boardgame skill，本工具链不碰 catalog.ts）。
- 不做美术/组件图形设计。
- 样本档案只存提炼后的结构、机制与数值，**不照搬规则书原文表达与美术**（机制/数值不受版权保护，表达受保护）。
- 不 commit（用户约定）；不引入新运行环境（Node 之外）。
- 失败即反目标：平衡结论无数据无证据（拍脑袋）；借鉴无来源标注；模拟不可复现；未经用户确认就推进到下一阶段或覆盖用户改判。

## Constraints

- 环境：Windows + Git Bash；Node/npm 已有（boardgame-ui 用 vitest + TS），工具包沿用同款栈。
- 工具包依赖最小化：`yaml`、`zod`、`tsx`、`typescript`、`vitest`（dev）；PRNG 自带实现（如 mulberry32），不引随机数库。
- 联网调研用内置 WebSearch，可离线降级（纯知识推理 + 标注置信度），与 import-boardgame 的证据策略一致。
- 机制标签词汇与 catalog.ts 7 区对齐；样本判例（Splendor→card、Dice Throne/Avalon→narrative、Brass→heavy）沿用。
- TDD：脚本先写失败测试再实现（概率正确性对已知解析值、种子可复现性、schema 校验）。
- 报告与规则书默认中文（用户语言）；机制标签保留中英对照。

## Approaches

- **A 纯知识工作流（零代码）**：只有 skill + references，推演全靠对话内纸面跑局。一两天可用、离线，但平衡结论是推理不是数据，长对话易漂移。排除：满足不了"真数据验证"。
- **B（选定）知识工作流 + 数值模拟工具箱 + 样本库**：rubric/机制库做裁决框架，脚本对可参数化子系统做真实模拟，样本档案支撑 remix。准、稳、可复核，结构化格式为平台植入留路。工作量一两周级别。
- **C 可执行规则引擎 + 全自动对局**：规则 DSL + 解释器 + AI 玩家整局自我对局。验证最彻底且是平台通用引擎底座，但数月级大项目、每款游戏须完整编码。排除（本期）：太重；schema 为其预留兼容。

## 工作流要点（SKILL.md 承载）

- **设计主流程**：① 明确意图（用户点子结构化 / 从机制库+样本出 2~3 个创意供挑选）→ ② 起草 game.yaml + rules.md → ③ 样本对照（借鉴哪些特征、来源、差异）→ ④ 数值验证（对可参数化子系统跑模拟，报告入 sims/）→ ⑤ 评审（rubric 逐条过）→ ⑥ 用户裁决迭代 → ⑦ 导出。②③⑤⑦ 前均有用户确认点；用户改判以用户为准。
- **analyze 工作流**（建样本档案）：收集信息（WebSearch 佐证 / 用户喂规则书）→ 按 schema 拆解 → 写 analysis 段（为什么好玩、可 remix 特征、坑）→ 标注来源与置信度 → 用户确认 → 入 design/samples/。抽象棋类（象棋/围棋/五子棋）经济子系统为空，档案侧重结构与平衡特性。
- **模拟调用**：agent 经 Bash 跑 `npm run sim -- <子命令> --config <yaml>`；快速 ad-hoc 查询支持命令行参数直跑。报告落工作区，平衡论断引用报告路径。

## 实现语义裁定（builder 评审后，2026-11-20）

评审提出 3 个猜错会返工的问题，裁定如下（均为实现者依据已定路线推出的决定，非用户新增决策，用户批准本文档时一并确认）：

1. **机制词汇 = 开放超集，工具包自持数据文件**。封闭 enum 会废掉"设计新游戏"核心用途。`tools/boardgame-design/data/mechanisms.yaml` 是扩展词汇的单一事实来源：收录 catalog.ts 全部区級与游戏级标签 + 设计所需扩展机制（拍卖、推轨、秘密目标等），每个机制声明归属分区（允许多区；游戏归区仍按主导机制，沿用 import-boardgame 判例）。schema 的 mechanisms 字段按该词汇表校验；新机制须先入词汇表（含分区映射与理由）再使用。一致性测试直接相对路径 import `catalog.ts`（纯 TS、无 Vue 依赖），断言其全部标签 ⊆ 词汇表。`references/mechanisms.md` 与词汇表同源对应，承载设计指导。
2. **经济模拟器 = 静态投影 + 可选声明式消费策略，两层**。基础层：按配置费率做 N 回合收支投影 + 结构性检查（资源有无沉没口、产出/消耗净流量）。可选层：模拟配置中声明**消费策略参数**（贪心/优先级清单等），模拟器按策略跑 N 回合——策略是用户/agent 配置的参数，**不是 AI 决策**，不违反 C 路线排除条款。"卡死"操作化定义：给定策略下连续 K 回合无行动可负担，或资源无限堆积且无沉没口（K 可配）。平衡论断须注明用的是哪一层。
3. **game.yaml 是数值单一事实来源**。sim 配置 = 引用 game.yaml 路径 + 子系统选择 + sweep 覆盖项 + 种子 + 局数，运行时合并，杜绝手工转录漂移。命令行参数直跑仅供快速探索，**不作为平衡证据**；落盘报告必须来自配置驱动的运行。
